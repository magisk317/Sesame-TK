# Sesame-TK 运行验证记录

本文保留历史运行和会话分析中的可复用结论。它不是当前代码契约；涉及设备行为时，必须重新采集手机端日志、包版本和前台页面。

## 2026-08-06 生命周期与任务运行

### 已确认

- Task runner、页面监控、能量蹲点和 RPC bridge 已逐步收敛到可取消的会话边界。
- 会话销毁先失效旧会话、停止调试入口并取消任务，再排空正在执行的 RPC；重建时重新发布 bridge 和调试服务。
- `SimplePageManager` 使用弱引用保存页面对象，延迟页面任务在会话重置时可取消。
- AntSports 的隐藏配置读取增加初始化保护；缺少依赖时跳过相关分支，不再因 `lateinit` 读取导致运行时异常。

### 历史证据

- `testDebugUnitTest`、`lintDebug` 和 `assembleDebug` 在多轮改动后通过，测试数量从 12 增至 14。
- HP 端安装后的日志确认 APK 被 Xposed 加载，森林任务出现实际收取记录，AntSports 新时间窗没有 `runJava error` 或 `UninitializedPropertyAccessException`。
- 强制停止支付宝服务后，日志出现目标 Service 的 `onDestroy`，随后新会话重新加载；能量蹲点任务按账号恢复，销毁重建窗口没有 NPE、未初始化字段或非法城市 ID。

### 尚未闭环

- 账号切换而非进程销毁的路径仍需用手机端日志验证旧任务和旧 RPC 不会穿透。
- 调试 HTTP 端口停止和重建后的恢复需要端口级证据。
- Home、日志、设置和 Compose 设置页面的顶部灰条仍缺少逐页真机截图验证。

## 2026-08-17 福气鱼塘 RPC

### 已确认的协议边界

- 页面和模块使用 `antfishpond` / `GameCenter` 场景；主动请求使用页面已观察到的来源参数。
- 页面状态查询包括 `fishpondIndex`、`fishpondSyncIndex`、`fishpondAngle` 和 `triggerSubplotsActivity`；任务页包括 `listTask`、`sign` 和肥料换竿；任务完成/领奖使用 `finishTask` 和 `receiveTaskAward`。
- 签到以 `signInfo.list[]` 中当天项目为准。肥料换竿数量受服务端可兑换次数、肥料余额和单次价格共同限制。
- `fishpondAngle success=true` 不等于捕鱼成功。只有同步后鱼竿减少且总鱼重增加，才记录为成功并继续；福利鱼挑战、无进展、安全验证或业务错误应立即停止。
- 鱼塘奖励必须按实时同步状态领取；没有明确页面动作合同的跳转、分享和加首页任务不伪造完成。

### 验证状态

- 已有真机样本覆盖普通鱼成功、福利鱼无进展、页面 token 捕鱼和领取明日鱼竿。
- 最新 facade、领奖、兑换和跨循环去重逻辑当时尚未重新安装到真机；后续仍需新的授权窗口和手机日志验收。
